A entrada do prédio

A Portaria do Tribunal

O Controller é a portaria: por onde as requisições HTTP entram, apresentam seus documentos e recebem uma resposta. Hoje testamos essa portaria com MockMvc, sem abrir as portas de verdade.

A camada web

@RestController

@RestController
@RequestMapping("/tarefas")
public class TarefaController {

    @GetMapping("/{id}")
    public Tarefa buscarPorId(@PathVariable Long id) {
        return tarefaService.buscarPorId(id);
    }
}

O Controller não tem regra de negócio — apenas recebe a requisição e delega ao Service.

Exemplo

Um teste de Controller

mockMvc.perform(get("/tarefas/1"))
    .andExpect(status().isOk())
    .andExpect(jsonPath("$.titulo").value("Estudar Spring"));

Verificamos o status HTTP E o conteúdo do corpo JSON — sem subir um servidor de verdade.

Diferentes cenários

Status codes esperados

when(tarefaService.buscarPorId(99L))
    .thenThrow(new TarefaNaoEncontradaException());

mockMvc.perform(get("/tarefas/99"))
    .andExpect(status().isNotFound()); // 404
Contexto importa

@Mock vs. @MockBean

@Mock

  • Usado com MockitoExtension, sem Spring
  • Para testes de Service isolados (Aula 12)

@MockBean

  • Usado dentro do contexto do Spring
  • Cria o mock E o registra no container, substituindo o bean real
Fixação rápida

Quiz

1. O que @WebMvcTest sobe no contexto do Spring?

Toda a aplicação, incluindo banco de dados
Apenas a infraestrutura web (Controllers, filtros, serialização JSON)
Apenas os Repositories

2. Para que serve jsonPath("$.titulo")?

Para definir o endpoint que será chamado
Para navegar e verificar um valor específico dentro do corpo JSON da resposta
Para configurar o banco de dados de teste
