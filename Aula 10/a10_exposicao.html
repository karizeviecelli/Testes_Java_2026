Duas métricas diferentes

Cobertura de linha vs. de branch

if (idade < 18) {
    return "menor de idade";
} else {
    return "maior de idade";
}

Um teste com idade=20 cobre 100% das LINHAS, mas só 50% dos BRANCHES — nunca passou pelo "if".

A armadilha

100% de cobertura ≠ ausência de bugs

public int dividir(int a, int b) {
    return a / b; // e se b for 0?
}

@Test
void dividirDeveFuncionar() {
    assertEquals(5, dividir(10, 2)); // 100% cobertura, mas b=0 nunca testado!
}
Postura correta

Cobertura como diagnóstico vs. como objetivo cego

✗ OBJETIVO CEGO

  • "Preciso bater 100% a qualquer custo"
  • Testes escritos só para "pintar a linha de verde"
  • Asserções fracas ou ausentes

✓ FERRAMENTA DE DIAGNÓSTICO

  • "O que eu esqueci de testar?"
  • Cobertura aponta lacunas, não garante qualidade
  • Complementada por bom raciocínio de casos de teste
Fixação rápida

Quiz

1. Um método com um único if/else tem 100% de cobertura de LINHA com apenas um teste. Isso garante 100% de cobertura de BRANCH?

Sim, sempre
Não, é preciso testar os dois caminhos (if e else) separadamente
Só se o método for void

2. 100% de cobertura de código significa que o código está livre de bugs?

Sim, é uma garantia matemática
Não — cobertura mede execução, não qualidade das verificações
Sim, mas só para classes com menos de 50 linhas
