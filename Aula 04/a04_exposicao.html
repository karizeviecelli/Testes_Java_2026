Aula 04 · Teste de Sistemas

Asserções, exceções e padrão AAA com JUnit 5

Vamos construir uma classe ContaBancaria e testá-la do começo ao fim. Cada exemplo inclui código completo, comentários e a evidência que o teste pretende apresentar.

Organizar

Criar objetos e preparar o estado inicial.

Agir

Executar o comportamento testado.

Assert

Verificar

Comparar o resultado obtido com o esperado.

Objetivo: testar resultados, exceções, mensagens, múltiplos atributos e cenários que não devem lançar erros.
1 · Código de produção

A classe que será testada

ContaBancaria.java
package org.example;

public class ContaBancaria {
    private String titular;
    private String numeroConta;
    private double saldo;

    // Construtor para uma conta com saldo inicial.
    public ContaBancaria(String titular,
                           String numeroConta,
                           double saldoInicial) {
        this.titular = titular;
        this.numeroConta = numeroConta;
        this.saldo = saldoInicial;
    }

    // Sobrecarga: conta sem valor começa com saldo zero.
    public ContaBancaria(String titular,
                           String numeroConta) {
        this(titular, numeroConta, 0.0);
    }
}
Encapsulamento

Os atributos são privados e o saldo muda somente pelas operações permitidas.

Construtor principal

Armazena os três parâmetros; nenhum valor fica esquecido.

Sobrecarga

O construtor de dois argumentos chama o principal com saldo zero.

2 · Regras de negócio

Depósito e saque com validações

ContaBancaria.java — métodos
public void depositar(double valor) {
    // Rejeita depósito igual ou menor que zero.
    if (valor <= 0) {
        throw new IllegalArgumentException(
            "O valor do depósito deve ser maior que zero."
        );
    }
    saldo += valor;
}

public void sacar(double valor) {
    // Sem esta validação, sacar -50 aumentaria o saldo.
    if (valor <= 0) {
        throw new IllegalArgumentException(
            "O valor do saque deve ser maior que zero."
        );
    }

    if (valor > saldo) {
        throw new IllegalArgumentException(
            "Saldo insuficiente"
        );
    }
    saldo -= valor;
}
Valor negativo

Um pequeno sinal poderia virar uma grande confusão bancária.

Mensagem exata

O teste deve esperar Saldo insuficiente, sem reticências.

3 · Encapsulamento

Getters e fechamento da classe

ContaBancaria.java — getters
public String getTitular() {
    return titular;
}

public String getNumeroConta() {
    return numeroConta;
}

public double getSaldo() {
    return saldo;
}

// Não existe setSaldo().
// O saldo só muda por depositar() ou sacar().
Sem setSaldo

Um setter permitiria alterar o saldo sem respeitar as regras.

Observação do estado

Os testes verificam os resultados por meio dos getters.

5 · Padrão AAA

Depósito deve aumentar o saldo

Arrange, Act e Assert
@Test
void depositarValorValidoDeveAumentarSaldo() {
    // ARRANGE: conta com saldo inicial zero.
    ContaBancaria conta = new ContaBancaria(
        "Maria", "123"
    );

    // ACT: executa a ação testada.
    conta.depositar(100.0);

    // ASSERT: esperado, obtido e tolerância para double.
    assertEquals(100.0, conta.getSaldo(), 0.001);
}
Esperado

100.0 é o resultado previsto pela regra.

Obtido

getSaldo() devolve o resultado real.

Delta

0.001 é a tolerância para comparar valores double.

6 · Exceções esperadas

Saldo insuficiente com assertThrows

Teste completo da exceção
@Test
void sacarValorMaiorQueSaldoDeveLancarExcecao() {
    // ARRANGE: a nova conta começa com saldo 0.0.
    ContaBancaria conta = new ContaBancaria(
        "Maria", "123"
    );

    // ACT + ASSERT: executa sacar() e captura a exceção.
    IllegalArgumentException excecao = assertThrows(
        IllegalArgumentException.class,
        () -> conta.sacar(50.0)
    );

    // A exceção ocorreu e foi capturada, então esta linha roda.
    System.out.println(
        "Mensagem capturada: " + excecao.getMessage()
    );

    // A mensagem deve coincidir exatamente com a classe.
    assertEquals("Saldo insuficiente", excecao.getMessage());
}
A exceção ocorre

assertThrows captura o erro; por isso o teste continua.

Lambda

() -> conta.sacar(50.0) é a ação que deve falhar.

Comparação literal

Espaços, letras, acentos e pontuação contam.

7 · Caminho de sucesso

Saque válido não deve lançar exceção

assertDoesNotThrow
@Test
void sacarComSaldoDisponivelDeveReduzirSaldo() {
    // ARRANGE: prepara saldo suficiente.
    ContaBancaria conta = new ContaBancaria(
        "Maria", "123"
    );
    conta.depositar(100.0);

    // ACT + ASSERT: deve terminar normalmente.
    assertDoesNotThrow(() -> conta.sacar(40.0));

    // ASSERT: 100 - 40 = 60.
    assertEquals(60.0, conta.getSaldo(), 0.001);
}
Não use assertThrows

Neste cenário nenhuma exceção é esperada.

Duas evidências

A operação termina sem erro e o saldo final fica correto.

8 · Valores inválidos

Depósito zero e saque negativo

Testes de fronteira
@Test
void depositarZeroDeveLancarExcecao() {
    ContaBancaria conta = new ContaBancaria("Maria", "123");

    IllegalArgumentException excecao = assertThrows(
        IllegalArgumentException.class,
        () -> conta.depositar(0.0)
    );

    assertEquals(
        "O valor do depósito deve ser maior que zero.",
        excecao.getMessage()
    );
}

@Test
void sacarValorNegativoDeveLancarExcecao() {
    ContaBancaria conta = new ContaBancaria(
        "Maria", "123", 100.0
    );

    assertThrows(
        IllegalArgumentException.class,
        () -> conta.sacar(-20.0)
    );
}
Partições

Teste valores positivos, zero e negativos.

Fronteira

O zero fica exatamente no limite entre aceito e rejeitado.

9 · Múltiplas evidências

Agrupando verificações com assertAll

Teste do construtor
@Test
void construtorDeveInicializarTodosOsAtributos() {
    // ARRANGE + ACT
    ContaBancaria conta = new ContaBancaria(
        "João", "99999-9"
    );

    // ASSERT: todas as verificações serão executadas.
    assertAll(
        "Dados iniciais da conta",
        () -> assertEquals("João", conta.getTitular()),
        () -> assertEquals("99999-9", conta.getNumeroConta()),
        () -> assertEquals(0.0, conta.getSaldo(), 0.001)
    );
}
Sem assertAll

A primeira falha interrompe o método de teste.

Com assertAll

O JUnit executa todas as lambdas e reúne as falhas.

10 · Caixa de ferramentas

Asserções mais usadas no JUnit 5

AsserçãoO que verificaExemplo
assertEqualsObtido igual ao esperado.assertEquals(60.0, saldo, 0.001)
assertNotEqualsValores diferentes.assertNotEquals(0.0, saldo)
assertTrue / assertFalseCondição verdadeira ou falsa.assertTrue(saldo > 0)
assertNull / assertNotNullReferência nula ou inicializada.assertNotNull(conta)
assertThrowsAção lança a exceção esperada.assertThrows(..., () -> sacar())
assertDoesNotThrowAção termina sem exceção.assertDoesNotThrow(() -> sacar())
assertAllExecuta um grupo de asserções.assertAll(() -> ..., () -> ...)
Mensagem de falha: assertEquals(esperado, obtido, "Saldo final incorreto"). Ela aparece apenas se a asserção falhar e não é a mensagem da exceção.
11 · Legibilidade

Nomes de testes contam pequenas histórias

✗ Vagos

  • teste1()
  • testSaque()
  • testeConta()
  • Não informam condição nem resultado.

✓ Descritivos

  • depositarValorValidoDeveAumentarSaldo()
  • sacarValorMaiorQueSaldoDeveLancarExcecao()
  • construtorDeveInicializarTodosOsAtributos()
Modelo: método testado + condição do cenário + comportamento esperado.
12 · Diagnóstico

Como interpretar uma falha

Exemplo de relatório
org.opentest4j.AssertionFailedError:
Expected :Saldo insuficiente...
Actual   :Saldo insuficiente
Expected

Texto escrito no primeiro argumento do assertEquals.

Actual

Valor retornado por excecao.getMessage().

Correção

assertEquals("Saldo insuficiente", excecao.getMessage()).

Antes de alterar o teste, confirme qual mensagem representa a regra de negócio. Classe e teste devem permanecer consistentes.
