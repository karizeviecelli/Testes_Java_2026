Prática guiada — ampliando o TarefaRepository

Siga os passos abaixo para adicionar e testar mais consultas customizadas no projeto integrador.

1
Adicionar o campo prioridade à entidade Tarefa
▶

Adicione um atributo prioridade (String: "ALTA", "MEDIA", "BAIXA") à entidade Tarefa.

@Entity
public class Tarefa {
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;

    private String titulo;
    private boolean concluida;
    private String prioridade;

    // construtores e getters/setters...
}
Lembre-se de atualizar o construtor para receber a prioridade, ou criar um setter para ela.
2
Adicionar consulta customizada por prioridade
▶

Adicione o método à interface, seguindo a convenção de nomes do Spring Data.

public interface TarefaRepository extends JpaRepository<Tarefa, Long> {
    List<Tarefa> findByConcluida(boolean concluida);
    List<Tarefa> findByPrioridade(String prioridade);
}
Nenhuma implementação é necessária — o Spring Data gera a consulta SQL a partir do nome "findByPrioridade".
3
Testar findByPrioridade
▶

Salve tarefas com prioridades diferentes e confirme que a busca filtra corretamente.

@Test
void findByPrioridadeDeveFiltrarCorretamente() {
    tarefaRepository.save(new Tarefa("Urgente", "ALTA"));
    tarefaRepository.save(new Tarefa("Rotina", "BAIXA"));

    List<Tarefa> altas = tarefaRepository.findByPrioridade("ALTA");

    assertEquals(1, altas.size());
}
Cada método @Test com @DataJpaTest roda em uma transação que é revertida ao final — os dados de um teste não "vazam" para o próximo.
4
Testar exclusão com deleteById
▶

Use o método herdado deleteById() e confirme que a tarefa não é mais encontrada.

@Test
void deleteByIdDeveRemoverTarefa() {
    Tarefa tarefa = tarefaRepository.save(new Tarefa("Temporária"));

    tarefaRepository.deleteById(tarefa.getId());

    assertTrue(tarefaRepository.findById(tarefa.getId()).isEmpty());
}
findById() retorna um Optional<Tarefa> — por isso usamos .isEmpty() em vez de comparar diretamente com null.
