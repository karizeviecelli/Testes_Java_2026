Conceito

Maven: build e dependências

Em vez de baixar um .jar manualmente, declaramos a biblioteca que queremos no pom.xml — o Maven baixa e organiza tudo.

meu-projeto/
├── pom.xml                ← o "regimento" do projeto
├── src/main/java/         ← código de produção (entidades)
└── src/test/java/         ← código de teste

A peça central

A dependência do JUnit 5

<dependency>
    <groupId>org.junit.jupiter</groupId>
    <artifactId>junit-jupiter</artifactId>
    <version>5.10.2</version>
    <scope>test</scope>
</dependency>

junit-jupiter é a dependência "guarda-chuva": traz a API de testes, o motor de execução e o suporte a testes parametrizados, tudo de uma vez.

Atenção

scope test vs. sem scope

✗ SEM SCOPE (padrão: compile)

  • Disponível em produção E em testes
  • Vai empacotada no .jar final
  • Não faz sentido para bibliotecas de teste

✓ SCOPE TEST

  • Disponível só durante compilação/execução de testes
  • Nunca vai para o artefato de produção
  • Uso correto para JUnit, Mockito, etc.
