Prática guiada — testando a classe Pedido

Siga os passos abaixo, na ordem, para escrever sua primeira classe de teste completa, com ciclo de vida (@BeforeEach) e múltiplos @Test.

1
Criar a entidade Pedido
▶

Em src/main/java, crie a classe Pedido com um atributo valorTotal (double), iniciado em 0.0.

public class Pedido {
    private double valorTotal;

    public void adicionarItem(double valor) {
        if (valor <= 0)
            throw new IllegalArgumentException("Valor do item deve ser positivo.");
        this.valorTotal += valor;
    }

    public double getValorTotal() { return valorTotal; }
}
Note que valorTotal começa em 0.0 por padrão em Java para tipos double — mas é boa prática deixar isso explícito no construtor em casos reais.
2
Criar a classe PedidoTest e o atributo de teste
▶

Em src/test/java, no mesmo pacote, crie PedidoTest com um atributo Pedido pedido.

class PedidoTest {
    private Pedido pedido;
}
Repare que a classe de teste NÃO precisa ser public — o padrão (package-private) já é suficiente para o JUnit 5 encontrá-la.
3
Adicionar o @BeforeEach
▶

Crie um método anotado com @BeforeEach que instancia um novo Pedido antes de cada teste.

@BeforeEach
void configurar() {
    pedido = new Pedido();
}
Não esqueça o import: "import org.junit.jupiter.api.BeforeEach;" no topo do arquivo.
4
Escrever os métodos @Test
▶

Escreva dois testes: um confirmando que o pedido nasce com valorTotal 0.0, e outro confirmando que adicionarItem() soma corretamente.

@Test
void pedidoDeveNascerComValorZero() {
    assertEquals(0.0, pedido.getValorTotal());
}

@Test
void adicionarItemDeveSomarAoTotal() {
    pedido.adicionarItem(50.0);
    pedido.adicionarItem(30.0);
    assertEquals(80.0, pedido.getValorTotal());
}
Não esqueça o import estático: "import static org.junit.jupiter.api.Assertions.assertEquals;"
5
Executar pelo IntelliJ e conferir o resultado
▶

Clique no ícone de "play" ao lado do nome da classe PedidoTest para rodar todos os testes de uma vez.

Tests passed: 2 of 2 test — 5ms
Se algum teste ficar vermelho, leia a mensagem de erro com calma — o JUnit sempre mostra o valor esperado (expected) vs. o valor obtido (actual).
