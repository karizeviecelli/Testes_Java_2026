Quando as peças funcionam juntas

2 · Questão-problema

Uma classe verde garante um sistema verde?

CalculadoraDescontoTest.java
@Test
void deveAplicarDesconto() {
    CalculadoraDesconto calc = new CalculadoraDesconto();
    assertEquals(90, calc.aplicar(100, 10), 0.001);
}
O que sabemos?

A calculadora produziu o resultado esperado.

O que não sabemos?

Se Pedido fornece o total correto e se os objetos colaboram.

Um componente correto isoladamente não prova que a integração está correta.
3 · Conceito

Unitário × Integração

CritérioUnitárioIntegração
FocoUma pequena unidadeColaboração entre componentes
DiagnósticoMais localizadoPode exigir investigação
ExemploProduto valida preçoPedido soma Produtos
Analogia da banda: testar o músico é unitário; testar a banda tocando junta é integração.
4 · Domínio

Produto será nossa primeira peça

Produto.java
public class Produto {
    private String nome;
    private double preco;

    public Produto(String nome, double preco) {
        if (preco <= 0) {
            throw new IllegalArgumentException(
                "Preço deve ser maior que zero"
            );
        }
        this.nome = nome;
        this.preco = preco;
    }

    public String getNome() { return nome; }
    public double getPreco() { return preco; }
}
Regra

Preço precisa ser positivo.

Pergunta

Que comportamentos merecem testes?

5 · Unitário

Testar Produto isoladamente

ProdutoTest.java
@Test
void deveCriarProdutoComPrecoCorreto() {
    Produto produto = new Produto("Teclado", 200);
    assertEquals(200, produto.getPreco(), 0.001);
}
O comportamento observado está concentrado em Produto. Portanto, este é um teste unitário.
6 · Colaboração

Pedido passa a depender de Produto

Pedido.java
public class Pedido {
    private List<Produto> produtos = new ArrayList<>();

    public void adicionarProduto(Produto produto) {
        produtos.add(produto);
    }

    public double calcularTotal() {
        double total = 0;
        for (Produto produto : produtos) {
            total += produto.getPreco();
        }
        return total;
    }
}
Integração

Pedido usa dados fornecidos por objetos Produto.

7 · Primeiro teste

Produto + Pedido

PedidoIntegracaoTest.java
@Test
void deveCalcularTotalDosProdutos() {
    Produto teclado = new Produto("Teclado", 200);
    Produto mouse = new Produto("Mouse", 100);
    Pedido pedido = new Pedido();

    pedido.adicionarProduto(teclado);
    pedido.adicionarProduto(mouse);

    assertEquals(300, pedido.calcularTotal(), 0.001);
}
Agora o resultado depende da colaboração entre objetos reais de Produto e Pedido.
8 · Organização

Arrange, Act e Assert

Arrange

Preparar objetos e dados.

Act

Executar o comportamento.

Assert

Comparar resultado e expectativa.

Como uma receita: separar ingredientes, preparar o prato e verificar o resultado.
9 · Terceira peça

CalculadoraDesconto

CalculadoraDesconto.java
public class CalculadoraDesconto {
    public double aplicar(double valor, double percentual) {
        return valor - (valor * percentual / 100);
    }
}
Primeiro teste esta classe isoladamente. Depois integre-a ao Pedido.
10 · Fluxo integrado

Produto → Pedido → Desconto

Pedido.java
public double calcularTotalComDesconto(double percentual) {
    double total = calcularTotal();
    CalculadoraDesconto calculadora =
        new CalculadoraDesconto();

    return calculadora.aplicar(total, percentual);
}
Entrada

Produtos somam R$ 300.

Regra

Desconto de 10%.

Saída

R$ 270.

11 · Evidência

Teste do fluxo completo desta integração

PedidoIntegracaoTest.java
@Test
void deveCalcularPedidoComDesconto() {
    Produto teclado = new Produto("Teclado", 200);
    Produto mouse = new Produto("Mouse", 100);
    Pedido pedido = new Pedido();

    pedido.adicionarProduto(teclado);
    pedido.adicionarProduto(mouse);

    double resultado = pedido.calcularTotalComDesconto(10);

    assertEquals(270, resultado, 0.001);
}

13 · Estratégia

A pirâmide de testes

Muitos unitários

Rápidos e localizados.

Integrações importantes

Verificam fronteiras e colaboração.

Poucos E2E

Validam fluxos completos do ponto de vista externo.

Os tipos se complementam; integração não substitui teste unitário.
