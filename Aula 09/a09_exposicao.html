O Que Exatamente Foi Dito ao Ator?

Na Aula 08 confirmamos QUE o ator foi chamado. Hoje vamos capturar exatamente o que foi passado a ele — e deixar o Mockito montar o palco inteiro automaticamente com @InjectMocks.

Automatizando a montagem

@InjectMocks

@Mock
private RepositorioUsuario repositorioMock;

@InjectMocks
private CadastroUsuario cadastro; // injetado automaticamente!

O Mockito olha o construtor, percebe a dependência e injeta o mock sozinho — sem "new" manual em cada teste.

Capturando o argumento com ArgumentCaptor

@Captor
private ArgumentCaptor<Usuario> usuarioCaptor;

verify(repositorioMock).salvar(usuarioCaptor.capture());
Usuario capturado = usuarioCaptor.getValue();

assertEquals("Ana", capturado.getNome());
Exemplo

Retornos consecutivos diferentes

when(bancoMock.consultarSaldo())
    .thenThrow(new RuntimeException("indisponível"))
    .thenReturn(1500.0);

// 1ª chamada: lança exceção
// 2ª chamada: retorna 1500.0

Perfeito para simular uma falha temporária seguida de sucesso — como uma segunda tentativa.

Quando usar cada um

verify simples vs. ArgumentCaptor

verify(mock).salvar(any())

  • Confirma QUE o método foi chamado
  • Não inspeciona detalhes do argumento

ArgumentCaptor

  • Confirma QUE foi chamado E permite inspecionar o argumento
  • Ideal quando o "conteúdo" importa, não só a chamada

Quiz

1. Para que serve o @InjectMocks?

Para criar um mock manualmente
Para injetar automaticamente os mocks declarados na classe testada
Para desativar um mock específico

2. Quando usar ArgumentCaptor em vez de verify simples?

Sempre, é obrigatório em todo teste com Mockito
Quando precisamos inspecionar detalhes do objeto passado ao mock
Só quando o método retorna void
