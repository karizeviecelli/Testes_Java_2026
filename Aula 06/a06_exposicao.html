Testes que contam uma história organizada

Uma suíte pode estar correta e ainda ser difícil de ler. Nesta aula, usaremos nomes, grupos e categorias para transformar resultados técnicos em documentação compreensível — enquanto testamos herança e polimorfismo.

@DisplayName

Traduz nomes técnicos para frases legíveis.

@Nested

Agrupa comportamentos relacionados.

@Tag

Classifica testes para execuções seletivas.

1 · Objetivos

O que você deverá conseguir fazer

Nomear evidências

Usar @DisplayName em classes e métodos.

Organizar contextos

Separar cenários com classes internas @Nested.

Filtrar execuções

Classificar testes com @Tag.

Testar polimorfismo

Verificar contrato comum e regra específica de cada subclasse.

Continuidade: testes parametrizados da Aula 5 podem existir dentro de grupos @Nested.
2 · O problema

O relatório técnico pode esconder a regra

Saída sem organização
FormaGeometricaTest
 ├─ teste1() ✔
 ├─ teste2() ✔
 ├─ teste3() ✔
 └─ teste4() ✘
Qual forma falhou?

O nome não informa se foi Quadrado ou Círculo.

Qual comportamento?

Não sabemos se era cálculo, validação ou polimorfismo.

Qual próximo passo?

O professor ou desenvolvedor precisa abrir o código para descobrir.

Testes são documentação executável. Se o relatório não comunica a regra, parte do valor da suíte foi perdida.
3 · DisplayName

Nomes legíveis no relatório

FormaGeometricaTest.java
import org.junit.jupiter.api.DisplayName;
import org.junit.jupiter.api.Test;

@DisplayName("Formas geométricas")
class FormaGeometricaTest {

    @Test
    @DisplayName("Quadrado de lado 4 deve ter área 16")
    void calcularAreaDoQuadrado() {
        Quadrado quadrado = new Quadrado(4.0);
        assertEquals(16.0, quadrado.calcularArea(), 0.001);
    }
}
Nome Java

Continua útil para manutenção e busca no código.

Nome exibido

Explica o cenário em linguagem natural.

Boa frase

Contexto + ação ou regra + resultado esperado.

4 · Nested

Agrupar por contexto ou comportamento

Estrutura da suíte
class FormaGeometricaTest {

    @Nested
    @DisplayName("Ao trabalhar com Quadrado")
    class TestesQuadrado {
        // Cálculo e validações do quadrado.
    }

    @Nested
    @DisplayName("Ao trabalhar com Círculo")
    class TestesCirculo {
        // Cálculo e validações do círculo.
    }
}
Classe interna

A classe marcada com @Nested não é static.

Leitura hierárquica

O relatório mostra grupos e testes como uma árvore.

Sem exagero

Agrupe quando o contexto melhora a leitura, não apenas para criar pastas.

5 · Ciclo de vida

Preparação compartilhada dentro do grupo

@BeforeEach em uma classe aninhada
@Nested
@DisplayName("Ao trabalhar com Quadrado")
class TestesQuadrado {
    private Quadrado quadrado;

    @BeforeEach
    void prepararQuadrado() {
        // Um novo objeto será criado antes de cada teste do grupo.
        quadrado = new Quadrado(4.0);
    }

    @Test
    void areaDeveSerDezesseis() {
        assertEquals(16.0, quadrado.calcularArea(), 0.001);
    }
}
Isolamento

Cada teste começa com uma nova instância.

Escopo

O campo existe apenas no grupo de Quadrado.

Evite dependência

Um teste nunca deve depender de outro ter executado antes.

6 · Tag

Classificar para executar seletivamente

Categorias da suíte
@Nested
@Tag("geometria-circular")
class TestesCirculo {

    @Test
    @Tag("rapido")
    void areaDeveUsarPi() {
        // Este teste pertence às duas categorias.
    }
}
Uma ou mais tags

Um teste pode pertencer a várias categorias.

Tag no grupo

Todos os testes aninhados recebem a categoria do grupo.

Uso comum

rapido, integracao, banco ou domínio funcional.

Tag não é decoração: defina nomes padronizados e uma finalidade real para o filtro.
7 · Herança

Um contrato comum para uma família de classes

FormaGeometrica.java
package org.example.formas;

public abstract class FormaGeometrica {

    // Toda forma concreta é obrigada a calcular sua área.
    public abstract double calcularArea();

    public String descricao() {
        return "Forma geométrica";
    }
}
abstract class

Representa o conceito geral e não pode ser instanciada diretamente.

Método abstrato

Define o que todas as subclasses devem oferecer.

Método concreto

Pode fornecer comportamento comum reaproveitável.

8 · Subclasses

Cada forma implementa o contrato à sua maneira

Quadrado.java
public class Quadrado extends FormaGeometrica {
    private final double lado;

    public Quadrado(double lado) {
        if (lado <= 0) {
            throw new IllegalArgumentException(
                "O lado deve ser maior que zero."
            );
        }
        this.lado = lado;
    }

    @Override
    public double calcularArea() {
        return lado * lado;
    }
}
Circulo.java
public class Circulo extends FormaGeometrica {
    private final double raio;

    public Circulo(double raio) {
        if (raio <= 0) {
            throw new IllegalArgumentException(
                "O raio deve ser maior que zero."
            );
        }
        this.raio = raio;
    }

    @Override
    public double calcularArea() {
        return Math.PI * raio * raio;
    }
}
9 · Polimorfismo

Mesmo tipo, comportamentos diferentes

Uso polimórfico
FormaGeometrica forma1 = new Quadrado(4.0);
FormaGeometrica forma2 = new Circulo(2.0);

// A variável tem o mesmo tipo declarado.
// O método executado depende do objeto real.
double area1 = forma1.calcularArea(); // 16.0
double area2 = forma2.calcularArea(); // 4π
Tipo da referência

FormaGeometrica.

Objeto real

Quadrado ou Circulo.

Despacho dinâmico

Java escolhe a implementação sobrescrita em tempo de execução.

10 · Estratégia de teste

Contrato comum e regras específicas

O que testarOndeExemplo
Contrato comumTeste polimórfico ou conjunto parametrizadoToda forma válida retorna área positiva.
Fórmula específicaGrupo da subclasseQuadrado usa lado²; Círculo usa πr².
Validação específicaGrupo da subclasseLado e raio devem ser positivos.
Comportamento herdadoUma vez por contrato, se não houver sobrescritadescricao() retorna o texto comum.
Testar somente pela superclasse pode esconder regras específicas. Testar apenas subclasses pode repetir o mesmo contrato. Equilibre os dois níveis.
11 · Suíte organizada

Juntando @Nested, @DisplayName e @Tag

Trecho completo do grupo Círculo
@Nested
@Tag("geometria-circular")
@DisplayName("Ao trabalhar com Círculo")
class TestesCirculo {

    @Test
    @DisplayName("Raio 2 deve produzir área igual a 4π")
    void calcularAreaDeveUsarPi() {
        Circulo circulo = new Circulo(2.0);

        assertEquals(
            Math.PI * 4,
            circulo.calcularArea(),
            0.0001
        );
    }
}
Nested

Cria o contexto de Círculo.

DisplayName

Explica o grupo e o cenário.

Tag

Permite executar somente geometria circular.

12 · Parametrização

Organização e dados trabalham juntos

Vários quadrados no mesmo grupo
@Nested
class TestesQuadrado {

    @ParameterizedTest(name = "lado {0} gera área {1}")
    @CsvSource({
        "1.0, 1.0",
        "2.0, 4.0",
        "4.0, 16.0"
    })
    void areaDeveSerLadoAoQuadrado(
            double lado,
            double esperado) {

        Quadrado quadrado = new Quadrado(lado);
        assertEquals(esperado, quadrado.calcularArea(), 0.001);
    }
}

13 · Diagnóstico

Erros comuns

@Nested em classe static

Remova static; o JUnit espera uma classe interna não estática.

DisplayName genérico

“Teste do círculo” ainda não informa cenário nem expectativa.

Tags inconsistentes

rapido, rápido e fast viram categorias diferentes.

Teste polimórfico superficial

Confirme resultados, não apenas que o método pode ser chamado.
