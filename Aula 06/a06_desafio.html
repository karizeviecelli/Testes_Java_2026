Desafio: hierarquia de pagamentos

Modele duas formas de pagamento, organize os testes por contexto e prove que o polimorfismo executa a taxa correta.

35:00
tempo sugerido
Pista:
abstract class Pagamento {
    protected double valor;
    abstract double calcularTaxa();
}

class PagamentoPix extends Pagamento {
    // taxa zero
}

class PagamentoCartao extends Pagamento {
    // taxa de 2,5%
}

Regras de negócio

Crie Pagamento, PagamentoPix e PagamentoCartao.

Todo pagamento possui valor maior que zero e implementa calcularTaxa(). Pix não tem taxa; cartão cobra 2,5% do valor.
  • Valor zero ou negativo deve lançar IllegalArgumentException.
  • Mensagem: “O valor deve ser maior que zero.”
  • Use referências do tipo Pagamento no teste polimórfico.
  • Superclasse abstrata criada com validação e método abstrato.
  • Pix e Cartão sobrescrevem calcularTaxa().
  • Classe de teste possui @DisplayName legível.
  • Existem grupos @Nested para Pix, Cartão e Polimorfismo.
  • Grupo de Cartão recebeu @Tag("cartao").
  • Taxa zero, taxa de 2,5% e valor inválido foram verificados.
  • Teste polimórfico usa assertAll e confirma os dois resultados.
  • Relatório final apresenta nomes claros e todos os testes verdes.

Desafio concluído 🎯

Adicione agora uma terceira subclasse, PagamentoBoleto, com taxa fixa de R$ 3,00. Se a suíte estiver bem organizada, o novo contexto encontrará seu lugar sem drama — quase civilizado demais para Java.
