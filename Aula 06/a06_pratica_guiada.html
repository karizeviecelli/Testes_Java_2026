Prática guiada — formas geométricas organizadas

Construa a hierarquia, organize a suíte por contexto e verifique as regras específicas e o comportamento polimórfico.

1Criar a superclasse abstrata▶

Crie o contrato comum em FormaGeometrica.java.

package org.example.formas;

public abstract class FormaGeometrica {
    // Obriga cada forma concreta a fornecer sua fórmula.
    public abstract double calcularArea();

    // Método concreto herdado pelas subclasses.
    public String descricao() {
        return "Forma geométrica";
    }
}
Tente instanciar FormaGeometrica. O compilador impedirá, pois a classe é abstrata.
2Implementar Quadrado com validação▶

A subclasse deve herdar de FormaGeometrica, validar o lado e sobrescrever o cálculo.

package org.example.formas;

public class Quadrado extends FormaGeometrica {
    private final double lado;

    public Quadrado(double lado) {
        if (lado <= 0) {
            throw new IllegalArgumentException(
                "O lado deve ser maior que zero."
            );
        }
        this.lado = lado;
    }

    @Override
    public double calcularArea() {
        return lado * lado;
    }
}
@Override pede ao compilador para confirmar que o método realmente sobrescreve o contrato.
3Implementar Círculo com validação▶

Repita a estrutura, mas use a regra π × raio².

package org.example.formas;

public class Circulo extends FormaGeometrica {
    private final double raio;

    public Circulo(double raio) {
        if (raio <= 0) {
            throw new IllegalArgumentException(
                "O raio deve ser maior que zero."
            );
        }
        this.raio = raio;
    }

    @Override
    public double calcularArea() {
        return Math.PI * raio * raio;
    }
}
O resultado usa Math.PI; os testes precisarão de delta.
4Criar a estrutura de testes aninhados▶

Prepare a classe de teste com três contextos: Quadrado, Círculo e Polimorfismo.

package org.example.formas;

import org.junit.jupiter.api.*;
import static org.junit.jupiter.api.Assertions.*;

@DisplayName("Hierarquia de formas geométricas")
class FormaGeometricaTest {

    @Nested
    @DisplayName("Ao trabalhar com Quadrado")
    class TestesQuadrado { }

    @Nested
    @Tag("geometria-circular")
    @DisplayName("Ao trabalhar com Círculo")
    class TestesCirculo { }

    @Nested
    @DisplayName("Ao usar formas polimorficamente")
    class TestesPolimorfismo { }
}
As classes internas não levam static. Caso contrário, o JUnit não as tratará como contextos aninhados.
5Adicionar cálculos e validações aos grupos▶

Inclua estes métodos nas respectivas classes aninhadas.

// Dentro de TestesQuadrado
@Test
@DisplayName("Lado 4 deve produzir área 16")
void areaDeveSerLadoAoQuadrado() {
    Quadrado quadrado = new Quadrado(4.0);
    assertEquals(16.0, quadrado.calcularArea(), 0.001);
}

@Test
@DisplayName("Lado zero deve ser rejeitado")
void ladoZeroDeveLancarExcecao() {
    IllegalArgumentException erro = assertThrows(
        IllegalArgumentException.class,
        () -> new Quadrado(0)
    );
    assertEquals("O lado deve ser maior que zero.", erro.getMessage());
}

// Dentro de TestesCirculo
@Test
@DisplayName("Raio 2 deve produzir área igual a 4π")
void areaDeveUsarPi() {
    Circulo circulo = new Circulo(2.0);
    assertEquals(Math.PI * 4, circulo.calcularArea(), 0.0001);
}
Cada grupo deve reunir tanto o caminho válido quanto as validações específicas da subclasse.
6Adicionar o teste polimórfico▶

Use o tipo da superclasse nas referências e verifique os resultados das implementações reais.

// Dentro de TestesPolimorfismo
@Test
@DisplayName("Cada objeto deve executar sua própria fórmula")
void cadaFormaDeveCalcularSuaArea() {
    FormaGeometrica forma1 = new Quadrado(3.0);
    FormaGeometrica forma2 = new Circulo(1.0);

    assertAll(
        () -> assertEquals(9.0, forma1.calcularArea(), 0.001),
        () -> assertEquals(Math.PI, forma2.calcularArea(), 0.0001)
    );
}
O teste não chama métodos específicos de Quadrado ou Círculo: ele usa apenas o contrato FormaGeometrica.
